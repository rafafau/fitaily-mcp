# Training setup

## When to use

- “I ran 5 km in 28 minutes”, “log yesterday's ride”.
- “Build me a 3-day push/pull/legs template”, “add incline press to my plan”.
- “What exercises work the lats?”, “rename my Upper A template”.

## When not to use

- Reviewing history, PRs or muscle balance → `training-review`.
- Nutrition, recipes or body measurements → the nutrition/progress skills.

## Workflow — log a cardio session

1. Collect `type` (run, ride, walk…), `name`, `durationMin`, optional `distanceKm`,
   `caloriesBurned`, `date` (ISO).
2. Show a one-line summary and wait for confirmation.
3. `log_activity`. Strength sessions cannot be created here — say so and point to the app.

## Workflow — create a strength template

1. Clarify the goal: days per week, split, equipment, experience.
2. Resolve every movement with `search_exercises` (`search`, `category`, `equipment`).
   **Never invent an `exerciseId`.** Use `get_exercise` when the name is ambiguous.
3. Build `exercises[]`: `exerciseId`, `sets` (1–20), `reps` (free string such as `"8-12"`),
   `orderIndex`, optional `dayOfWeek` (1–7).
4. Show the full table (exercise, sets × reps, day) and **wait for confirmation**.
5. `create_workout_plan` with `name`, optional `description`, `exercises[]`.
6. Read it back with `get_workout_plan` and confirm the saved order.

## Workflow — edit, replace or delete

- `get_workout_plans` (`origin: "standalone"` to exclude templates generated by a training
  plan; `origin: "all"` includes them) → `get_workout_plan` for the current contents.
- `update_workout_plan`: send only changed fields. `exercises` **replaces the whole list**,
  so include the unchanged exercises too.
- `delete_workout_plan` is destructive: quote the template name before asking.

## Workflow — cancel a session

- `log_activity` has no matching delete tool in this server. If the user wants to remove an
  activity, explain that it has to be done in the Fitaily app.

## Tool cheat sheet

| Tool                  | Use it for            | Key arguments                                                                  |
| --------------------- | --------------------- | ------------------------------------------------------------------------------ |
| `log_activity`        | cardio/manual session | `type`, `name`, `durationMin`, `distanceKm?`, `caloriesBurned?`, `date?` (ISO) |
| `search_exercises`    | find exercise ids     | `search?`, `category?`, `equipment?`, `limit?` (≤50)                           |
| `get_exercise`        | exercise details      | `id`                                                                           |
| `get_workout_plans`   | list templates        | `limit?`, `origin` (`standalone                                                | plan_template | all`) |
| `get_workout_plan`    | one template          | `id`                                                                           |
| `create_workout_plan` | new template          | `name`, `description?`, `exercises[]`                                          |
| `update_workout_plan` | edit template         | `id` + changed fields (`exercises` replaces)                                   |
| `delete_workout_plan` | remove template       | `id`                                                                           |

## Guardrails

- Exercise ids come only from `search_exercises` / `get_exercise`.
- `reps` is text, not a number: keep ranges and qualifiers (`"AMRAP"`, `"8-12"`).
- A template generated by a training plan has `origin: PLAN_TEMPLATE` and is hidden from the
  app's workout library — do not “fix” it with `update_workout_plan` unless the user asks.
- Confirm the whole template once, not exercise by exercise (unless the user is drafting).
- No medical advice; if the user reports pain, stop programming and suggest a professional.

## Errors

| Error                                | What to tell the user                                 |
| ------------------------------------ | ----------------------------------------------------- |
| `403 Missing scope: training:write`  | Reconnect and allow training write access.            |
| Backend validation on an exercise id | The catalog changed — search again for that movement. |
| `404` on an id                       | The template was deleted; list templates again.       |
| `502`                                | Fitaily is unreachable; retry shortly.                |

## Examples

**User:** “I ran 6 km in 34 minutes this morning.”
**Assistant:** “Run, 6 km, 34 min, today — log it?” → on “yes”: `log_activity`
(`type: "run"`, `name: "Morning run"`, `durationMin: 34`, `distanceKm: 6`).

**User:** “Make me an upper/lower split, 4 days.”
**Assistant:** `search_exercises` for the chosen movements → proposes Upper A / Lower A /
Upper B / Lower B with sets × reps → on “yes”: `create_workout_plan` → `get_workout_plan`
to show the saved order.
